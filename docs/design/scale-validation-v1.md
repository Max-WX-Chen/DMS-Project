# R06–R11、R14 规模数据与恢复实测

2026-11-18 在 Windows 本机的独立 XAMPP MariaDB 10.4.32 实例完成。处理器为 AMD Ryzen 9 8945HX，PHP 8.2.12，InnoDB 缓冲池 128 MiB，`innodb_flush_log_at_trx_commit=1`，读取隔离级别 READ COMMITTED。生成库与空库恢复的 11 张表行数逐项相同，均为 **134,502 行，平均 12,227.45 行／表**。预约、出勤分别超过 50,000 行。

## 生成并复跑

1. 打开两个全新的隔离数据库，连接操作所用账号可在该测试库建表、创建例程及触发器。按部署说明配置本机 `FORM_CONFIG`。计时脚本另需该测试库的 DELETE 权限，应用的日常账号按部署文档配置。
2. 在第一个数据库中依次导入 `database/form_club.sql` 和 `database/scale_fixture.sql`。先建 2,000 名合成会员及对应年卡订单，再按 200 天、3 个场地和每日 6 个时段生成 3,600 场课程。每场有 15–20 个预约，涵盖取消、签到和缺席，部分成功订单另有失败的付款尝试。相同导入日得到相同的逻辑数据。
3. 在仓库根目录运行 `C:\xampp\php\php.exe tests\scale-benchmark.php`。脚本检查数据规模、10 类一致性条件，逐表运行十轮增查删，然后采集六种业务查询的耗时及 EXPLAIN。每轮清理本轮创建的行，自增 ID 可有间隙。
4. 运行 `C:\xampp\php\php.exe database\export.php FORM_Club_full.sql`。导出器按主键顺序从数据库的同一只读快照取数，写出本版本的 11 张表、约束、3 个触发器和全部数据；目标文件必须为新文件。导入时由数据库重新计算虚拟列。将文件用 ZIP 压缩适合传输。
5. 在第二个空库选择导入解压后的全部 SQL，再次运行计时脚本。实际交付包中的单个 SQL 已按此路径恢复，解压后 SHA-256 为 `8132F24118F4E65773C8856718411CCB65DBCF784A49BA4B2F71E9DE4CF4E63B`。完整快照固定在导出日；小库的交互演示日期随导入日生成。

## 数据完整性与查询路径

生成库和恢复库分别独立检查了订单成功状态与付款、会籍的对应关系，套餐和周期天数，购买者及预约者角色，会籍时间并集覆盖，教练重叠，场地重叠，会员重叠，签到合法性，结课未结算和容量。十项违规记录数均为 0。

| 恢复库业务查询 | 中位数 ms | 最大值 ms | 查询参数及路径 |
|---|---:|---:|---|
| 未来课表 | 0.202 | 0.276 | 从导入当日向后取 20 行，使用 ix_schedule。 |
| 个人预约 | 0.254 | 0.515 | 会员 1005，取最近 20 行，使用 uq_member_session 后连接场次与课程。 |
| 单场名单 | 0.340 | 0.481 | 场次 2050，使用 ix_roster、用户主键与 uq_attendance_booking。 |
| 会员周期 | 0.221 | 0.376 | 会员 1005 的已付款订单，使用 ix_order_owner 和 uq_membership_order。 |
| 收款金额 | 2.843 | 3.478 | 一年范围、成功收款。实际计划从 3 条套餐版本出发连接订单和付款。 |
| 出勤统计 | 13.555 | 14.750 | 近 30 天、已结课的有效预约，使用课表、名单和出勤索引。 |

运行脚本含对应完整 SQL。逐表样本数、P95、中位数、最大值和优化器选择的具体索引见 [恢复库原始结果](scale-results-v1.json)。此版记录已交付索引下的实测基线；移除索引的对照实验尚未执行。
