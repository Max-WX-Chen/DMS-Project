2026 年 11 月 18 日。基线为 PR #5 合并后的 `main`，业务规则采用 `Requirement.md` v1.4 的 B04、B12–B14 及 W01–W06，页面按 V01–V16 对照。

## 场次名单与签到

排课页原先将六个场次都链接至 S101 的 Power Flow 名单。现在按场次 ID 指向各自的名单。即使相同课程在不同时间开课，S102 和 S104 也会展示各自的场次。S106 已取消，显示取消状态并关闭签到，不会生成缺席记录。

原 Sam 签到链接跳到了 Jamie 的结果。现在两位会员有各自的结果页和更新后的名单。两条签到示例相互独立。结课样例也独立，它演示的是 Jamie 已到、Sam 未到的另一种结果。

## 续费提示

修改了我的会籍、结账说明及 30、90、365 天续费结果。会员可提前购买。付款确认后，新周期从付款确认时间与最后一个已付款周期结束时间的较晚者开始。如果三个月续费周期已经接到 2027 年 4 月 1 日，下一笔提前确认的续费从该日接续，即使当前会籍仍在 1 月 1 日到期。未付款或取消的订单不占用续费时间。

续费结果入口为套餐列表 → 选择 90 天 → 模拟支付结果 → `membership-renewed.html`。这里的固定日期用于说明案例，实际开始日期由后端在付款确认时计算。

## 验证与后续

对实际 ZIP 解压后使用 Chromium 在 1440 和 390 像素宽度、禁用 JavaScript 的设置下检查了全部页面。浏览器检查 1,377 项链接及资源引用，逐个点击六个名单入口、两位会员签到和主要演示路径。四个会籍页面的续费说明与预期一致。完整结果记录于 [浏览器结果](../frontend/static-validation.json)。

小组可在联调时以场次 ID、预约 ID 与订单状态作为页面与后端的对应依据，再把固定示例替换成服务器结果。
