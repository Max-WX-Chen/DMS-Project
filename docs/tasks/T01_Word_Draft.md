## 3. 两页的内容安排

**第一页：Problem Description**

1. Problem and objectives：定义会籍、排课、预约和出勤分散时可能发生的问题及改进目标。
2. Motivation：说明场景直观、关系丰富、有事务与一致性学习价值；没有杜撰实地调研。
3. Scope and information：单中心、多场地、Member／Admin、十一类业务信息及拟采用技术。
4. Planned features：账号、购买续费、排课、预约取消、出勤、查询统计六类功能。
5. Core assumptions：一单一个套餐版本、整单模拟或线下收款、独立会籍周期、一场次一个教练和场地。

正文不含标题约 367 个英文词。采用英文是沿用此前建议，不表示老师材料已经明确强制英语；若老师另有要求，应调整。

**第二页：Draft ER Model — Text and Tables**

- 实体表：十一实体、各自标识与主要信息。
- 联系表：十条联系、左到右基数、右侧记录归属与条件。
- 业务约束：会员权限、付款尝试与开通、不可变套餐版本、连续会籍覆盖、容量冲突、预约唯一性、出勤含义。

两张表都是 Word 原生表格，不是截图，可以修改文字和行列。属性是信息需求说明，不是冻结的 SQL 字段全集。

## 4. 应能讲清的模型含义

- **Course 与 ClassSession：**课程类型和一次实际排课不同，只有后者具有具体教练、场地、时间与名额。
- **Order 与 Payment：**一笔购买可以经历多次付款尝试，但最多成功结算一次，不因重试重复开通。
- **Membership：**每次成功购买保留一个周期；会员与套餐从来源订单追溯，避免复制后互相矛盾。
- **MembershipPlan：**一个标识代表一个套餐版本；首次被订单引用后，价格与时长固定，第一版金额从该版本取得。
- **Booking 与 Attendance：**预约不等于参加；出勤最多一条，未完成课程时可以尚无结果，缺席时签到时间为空。
- **基数：**`1 : 0..N` 表示每条右侧记录有一个左侧来源，而左侧可以没有或有多条右侧记录；`1 : 0..1` 表示最多一条。
- **条件规则：**“付款成功才且必须产生会籍”“不超容量”“不冲突”不是写出基数就自动成立，后续仍需约束、事务和验证。

示例：同一订单第一次付款失败、第二次成功，最终只有一个会籍周期；会员预约一节具体瑜伽课，合法签到后才有 PRESENT 出勤记录。

## 5. ER 形式与课程要求的区别

老师原文要求的是 ER diagram。本次按用户明确要求，用可编辑实体表和联系基数表表达候选 ER 结构，没有把文字表格伪称为已绘制的图形 ER 图。

正式提交前，应确认文字表格形式是否被接受；如果老师要求图形 ER，则基于同一十一实体／十联系生成图形并替换第二页，再重新检查总页数。原指南中的 Mermaid 候选图仍可作为转换依据。

这不影响本次 Word 的编辑和 PDF 转换，但不能据此宣称已满足最终图形交付要求。

## 8. 理解检查与交接

**为什么生成 Word 时还保留 Markdown？**  
Word 便于排版编辑，Markdown 便于在 PR 中阅读和比较；修改后应同步，避免版本不一致。

**Word 两页是否代表实际提交时永远两页？**  
不代表。添加成员、修改文字或字体替换都可能改变换行，最终 PDF 需要重新检查。

**这次已经完成图形 ER 与数据库实现了吗？**  
没有。本次交付是用户指定的 ER 文字表格版 Word，图形形式与实现验证属于后续明确任务。
