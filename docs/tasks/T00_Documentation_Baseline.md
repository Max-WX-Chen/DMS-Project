## 分支、main 和 PR 的区别

- **分支**：同一仓库中各自演进的版本线。创建分支时通常从某次提交出发；后续修改不会自动传到其他分支。
- **main**：通常是默认分支。本项目约定它保存全组共同使用的正式基线；这个用途来自小组约定，不是 Git 天生认为 main 内容必然更正确。
- **PR**：提出把任务分支的改动合并到目标分支，展示差异供讨论与审阅。PR 创建成功不等于已经合并。
- **合并**：将改动纳入目标分支。合并到 main 后，在 main 浏览、下载或拉取项目的成员才会得到这些文件。

可以把所有正式产出放在 main；这不等于日常工作都要直接修改 main。建议任务分支准备修改，PR 审阅后合并，main 中按文档、代码、数据库等目录组织。GitHub 不会把远程变化自动同步到每个人电脑，各工作副本仍要主动拉取。

**文件已在任务分支，为什么 main 看不到？**  
因为两个分支各自指向不同版本，尚未合并的修改不会自动出现在 main。

可以。通过合并纳入 main，同时按文件夹分类；成员从 main 获取共同基线。

**main 有了文件后还需要 PR 吗？**  
后续修改仍建议经过 PR，让组员看到差异、理解设计并发现冲突。
